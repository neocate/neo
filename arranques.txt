ARQUITECTURA FINAL: niveles_soporte.py (BACKTEST + LIVE)
════════════════════════════════════════════════════════════════════════

1. INVOCACIÓN
═════════════
python niveles_soporte.py <tf_objetivo> --cada<tf_alimentacion> --loop <intervalo>

Ejemplos:
  python niveles_soporte.py eth 5m --cada1m --loop 300
  python niveles_soporte.py eth 15m --cada3m --loop 400 --desde-dias 180

Parámetros:
  <tf_objetivo>         → 5m, 15m, 1h (timeframe de niveles a calcular)
  --cada<tf_alimentacion> → 1m, 3m, 5m (velas de entrada, menores)
  --loop <intervalo>    → segundos entre recalculaciones
  [--desde-dias N]      → limita histórico (opcional, para pruebas)


2. ESTRUCTURA ARCHIVOS
═══════════════════════
~/neo/herramientas/niveles/
├─ params_eth_5m.json           ← Parámetros dinámicos (editable en caliente)
├─ state_eth_5m.json            ← Estado: última vela procesada, modo (backtest/live)
├─ snapshots_eth_5m_cada1m.csv  ← OUTPUT: vela-por-vela con niveles
├─ .niveles_eth_5m.lock         ← Lock file (evita múltiples instancias)
└─ nivel_ETH_k3_toques3.json    ← Últimos niveles calculados (versionado)


3. FLUJOS
═════════

BACKTEST (histórico 1m → 5m):
  ┌─ Itera velas_eth_1m.csv cronológicamente
  ├─ Agrupa 1m → 5m (cada 5 velas 1m = 1 vela 5m nueva)
  ├─ Detecta niveles 5m
  ├─ Escribe snapshot CSV: (timestamp, precio_1m_actual, niveles_5m)
  ├─ Verifica: ¿llegué a HOY? (última vela histórica)
  └─ Si sí → modo LIVE

LIVE (sin histórico, espera nuevas velas):
  ┌─ Descargar_bit.py genera velas 1m nuevas
  ├─ niveles_soporte agrupa a 5m
  ├─ Calcula niveles
  ├─ Append CSV snapshot (continúa desde donde paró backtest)
  └─ Repite cada <intervalo>

7. LOCKS (ANTI-DUPLICADOS + ATOMIC WRITES)
════════════════════════════════════════════
Mutex file: .niveles_eth_5m.lock
  ├─ Previene 2 instancias simultáneas
  ├─ Timeout: 5s (espera, luego falla)
  └─ Se libera al terminar o error

Atomic writes:
  ├─ Escribe a temp file
  ├─ Reemplaza atómicamente (os.replace)
  └─ Si se interrumpe → archivo viejo intacto


8. DETECCIÓN DE CAMBIOS DE PARÁMETROS
══════════════════════════════════════
Cada iteración:
  ├─ Lee params_eth_5m.json
  ├─ Calcula hash(params)
  ├─ Si hash ≠ state.params_hash:
  │   ├─ Log: "⚠️  PARÁMETROS CAMBIARON"
  │   ├─ Recalcula TODO desde estado actual (NO desde inicio)
  │   └─ Actualiza state.params_hash
  └─ Continúa


9. DETECCIÓN AUTOMÁTICA BACKTEST → LIVE
═════════════════════════════════════════
En backtest:
  ├─ Itera histórico vela-por-vela
  ├─ Verifica: ¿última vela 1m en histórico < HOY?
  ├─ Si llegó a HOY:
  │   ├─ state.modo = "live"
  │   ├─ Espera próximas velas 1m desde descargar_bit.py
  │   └─ Continúa loop normal
  └─ Si está en vivo y llegan nuevas 1m:
      ├─ Procesa normalmente
      └─ Continúa CSV snapshot

11. BLOQUEOS (FLOWCHART)
═════════════════════════
Lock acquired (5s timeout)
  │
  ├─ Lee parámetros
  ├─ Si cambiaron:
  │   └─ Recalcula histórico desde estado actual
  │
  ├─ Lee state (última vela procesada)
  ├─ Si modo=backtest:
  │   ├─ Carga velas_eth_1m.csv desde última_vela_procesada
  │   ├─ Agrupa 1m → 5m
  │   ├─ Detecta niveles
  │   ├─ Escribe snapshot CSV
  │   ├─ Si llegó a HOY → modo=live
  │   └─ state.última_vela_procesada_ts = ahora
  │
  ├─ Si modo=live:
  │   ├─ Espera velas nuevas desde descargar_bit.py
  │   ├─ Procesa igual (agrupa, detecta, CSV)
  │   └─ state.última_vela_procesada_ts = ahora
  │
  ├─ Guarda state.json (atomic write)
  ├─ Guarda nivel_ETH_k3_toques3.json (atomic write)
  ├─ Guarda snapshot CSV (append, atomic)
  │
  ├─ Sleep <intervalo>
  └─ Repeat (o exit si Ctrl+C)

Lock released


12. CONSIDERACIONES
════════════════════
- CSV snapshot: append-only (nunca sobreescribe)
- State: actualiza después de CSV (evita pérdida de datos)
- Lock: timeout 5s (si otra instancia está lenta, espera)
- Backtest vs Live: automático, transparente
- Multi-instancia: lock file previene
- Parámetros dinámicos: detecta cambios cada iteración
